# POC Nuxt Studio — École de danse Saint-Jean

Bilingual (FR/EN) proof of concept for a Québec City dance school, built to exercise
[Nuxt Studio](https://nuxt.studio) on top of Nuxt UI and Nuxt Content v3.

## Stack

| Piece | Version | Role |
| --- | --- | --- |
| Nuxt | 4.5 | Framework (`app/` directory) |
| `@nuxt/ui` | 4.11 | Components and Tailwind theme |
| `@nuxt/content` | 3.16 | Typed content collections |
| `@nuxtjs/i18n` | 10.6 | FR default at `/`, EN at `/en` |
| `nuxt-studio` | 1.7 | Visual content editing |

## Getting started

```bash
npm install
npm run dev
```

Then open http://localhost:3000 and click the floating Studio button at the bottom left
to edit content. In dev mode every change is written straight back to `content/`.

Other scripts: `npm run build`, `npm run typecheck`, `npm run lint`.

## Routes

| FR | EN | Template |
| --- | --- | --- |
| `/` | `/en` | Homepage |
| `/calendrier` | `/en/calendar` | Calendar (classes, teachers, schedule) |
| `/contact` | `/en/contact` | Contact |

## Content model

Content is duplicated per locale under `content/fr/` and `content/en/`, and each folder maps
to its own collection in [`content.config.ts`](content.config.ts) (`pages_fr`, `classes_en`, ...).
Queries resolve the right suffix at runtime through
[`app/composables/useSchoolContent.ts`](app/composables/useSchoolContent.ts).

```
content/<locale>/
  pages/      index.md, calendar.md, contact.md   (markdown + typed frontmatter)
  classes/    one YAML file per class
  teachers/   one YAML file per teacher
  schedule/   weekly.yml, holding all time slots
```

The three calendar entities are linked by slug: a schedule entry references a class through
`classSlug`, and a class references its teacher through `teacher`.

Theme colours and school contact details live in [`app/app.config.ts`](app/app.config.ts) and are
exposed to the Studio interface through [`nuxt.schema.ts`](nuxt.schema.ts).

Placeholder images are generated by `node scripts/generate-placeholders.mjs`.

## Studio in production

Dev mode needs no configuration. Publishing from a deployed site additionally requires:

1. A GitHub or GitLab remote for this repository.
2. Repository details in `nuxt.config.ts`. These are auto-detected on Vercel, Netlify, GitHub
   Actions and GitLab CI; otherwise set `STUDIO_REPO_OWNER`, `STUDIO_REPO_NAME` and
   `STUDIO_REPO_BRANCH`.
3. OAuth credentials on the host, for example `NUXT_STUDIO_AUTH_GITHUB_CLIENT_ID` and
   `NUXT_STUDIO_AUTH_GITHUB_CLIENT_SECRET`.
4. An SSR-capable deployment built with `nuxt build`, since the auth callback needs a server route.

Editors then log in at `/_studio`. That route intentionally 404s on the dev server, where the
floating button replaces it.
